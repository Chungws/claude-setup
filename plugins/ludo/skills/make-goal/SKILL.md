# Make Goal — 자연어 → GOAL.md

## Input
- $ARGUMENTS: 자연어로 된 목표 (필수). 없으면 물어본다.

## 절차

### Step 1: 프로젝트 컨텍스트 수집 (silent)

1. **CLAUDE.md** — 프로젝트 규칙, 아키텍처
2. **코드 구조** — ls, pyproject.toml/package.json
3. **~/dapi-ssot/research/** — 관련 인사이트 검색
4. **기존 GOAL.md** — 있으면 읽고 "덮어쓸까요?" 확인

### Step 2: 갭 분석

사용자의 자연어 요청에서 GOAL.md에 필요한 항목을 추출하고, 빠진 것을 파악:

| 항목 | 필수 | 사용자가 언급했는가? |
|------|------|-------------------|
| 목표 (무엇을) | 필수 | ? |
| 요구사항 (구체적 동작) | 필수 | ? |
| 제약 (호환성, 성능, 설정) | 필수 | ? |
| 경계 조건 (에러, 엣지) | 필수 | ? |

**빠진 항목이 있으면 질문한다.** 한 번에 모든 질문을 묶어서:

```
GOAL.md를 만들기 위해 몇 가지 확인이 필요합니다:

1. {질문 1 — 예: "기존 dispatch 흐름과 호환되어야 하나요?"}
2. {질문 2 — 예: "타임아웃 시 에러 메시지는 어떤 형태여야 하나요?"}
3. {질문 3}
```

질문이 없으면 (충분히 상세하면) 바로 Step 3.

### Step 3: GOAL.md 생성

프로젝트 루트에 생성:

```markdown
# Goal: {제목}

## 목표
{사용자 요청 + 컨텍스트에서 파악한 의도}

## 요구사항
- {자연어에서 추출한 구체적 동작}
- {코드베이스 분석에서 도출한 추가 요구사항}

## 제약
- {사용자가 명시한 제약}
- {코드베이스에서 파악한 암묵적 제약 — 예: 기존 레이어 구조 준수}

## 경계 조건
- {에러 시 동작}
- {엣지 케이스}

## 참고
- {SSOT에서 찾은 관련 인사이트/노트}
```

### Step 4: 사용자 확인

생성된 GOAL.md를 보여주고 확인:

```
GOAL.md를 생성했습니다. 확인해주세요:

{GOAL.md 내용}

수정할 부분이 있으면 말씀해주세요.
확인되면 `/ludo:go`로 빌드를 시작할 수 있습니다.
```

수정 요청이 있으면 반영 후 다시 보여준다.

## 규칙
- 사용자가 한 줄만 줘도 GOAL.md를 만들 수 있어야 한다 — 나머지는 질문 + 코드베이스 분석으로 채움
- 과도한 요구사항 부풀리기 금지 — 사용자가 말한 것 + 코드베이스에서 필수인 것만
- 제약은 코드베이스에서 파악한 암묵적 제약도 포함 (레이어 규칙, 테스트 요구 등)
- **이 스킬만 유일하게 사용자와 대화** — 나머지 ludo 스킬은 파일만 읽음
