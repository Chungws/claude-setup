# Orchestrate — Goal → Skill Pipeline Planner

## Trigger
사용자가 `/orchestrate {목표}` 또는 "전체 계획 세워줘", "파이프라인 짜줘" 등으로 요청할 때.

## Input
- $ARGUMENTS: 달성하려는 목표 (필수)

## Phase 1: 목표 분석

1. `$ARGUMENTS`에서 목표 유형 파악:
   - **탐색형**: 모르는 걸 알아내야 함 → research 계열
   - **검증형**: 가설 확인 → experiment 계열
   - **구축형**: 만들어야 함 → plan + TDD
   - **개선형**: 더 좋게 → experiment 또는 refactor
   - 혼합 가능
2. `~/dapi-ssot/`에서 관련 기존 리서치/인사이트 검색 — 이미 있는 자산 파악
3. 현재 프로젝트의 PLAN.md가 있으면 읽고 맥락 파악

## Phase 2: 스킬 매핑

컨텍스트에 로드된 스킬 description 목록에서 필요한 스킬을 선택한다.
스킬 목록을 하드코딩하지 않는다 — 실행 시점에 사용 가능한 스킬을 기준으로 매핑.

각 스텝에 대해 결정할 것:
- **스킬**: 어떤 스킬 또는 일반 작업 (plan mode, TDD 등)
- **SOT 입력**: 이전 스텝의 산출물 또는 vault 기존 문서
- **SOT 산출물**: 이 스텝이 만드는 문서/아티팩트
- **검증**: 자동(tests, lint, analyze-plan, multi) 또는 사람
- **게이트**: 자동 진행(🤖) 또는 사람 큐(🧑)

### 사람 개입 판단 기준

**자동 진행 (🤖)**: 구현 세부사항, 리팩토링, 테스트, 품질 체크
**사람 큐 (🧑)**: 방향 설정, 범위 변경, 트레이드오프 선택, 고비용 작업, 메타 규칙 변경

## Phase 3: 사용자 출력

```
## 목표: {한줄 요약}

### 기존 자산
- {vault에서 찾은 관련 자료}
- 없으면 "관련 기존 자료 없음"

### 파이프라인

| # | 단계 | 스킬 | SOT 입력 | SOT 산출물 | 검증 | 게이트 |
|---|------|------|----------|-----------|------|--------|
| 1 | {명} | {스킬} | {입력} | {산출물} | {방법} | 🧑/🤖 |
| 2 | ... | ... | ... | ... | ... | ... |

### 🧑 사람이 결정할 것 (예상 {N}회)
1. Step {X}: {결정 내용}
2. Step {Y}: {결정 내용}

### 첫 번째 액션
{바로 실행 가능한 명령어}
```

## 규칙

- 단계 수 최소화 — 불필요한 세분화 금지
- 모든 스텝은 SOT 산출물을 만든다 — 산출물 없는 스텝은 스텝이 아니다
- 산출물은 vault 문서 또는 프로젝트 내 아티팩트 (코드, 테스트, 설정 등)
- 스킬 간 연결은 vault(~/dapi-ssot/)를 공유 인터페이스로 사용
- 파이프라인은 초기 제안이다 — 실행 중 필요하면 다시 `/orchestrate`로 재계획
- 실행은 이 스킬의 범위 밖. 매핑만 한다.
