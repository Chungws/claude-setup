# Scope Triage — 범위 밖 문제 발견 시 판단 기준

작업 중 범위 밖 문제를 발견하면, 무조건 스킵하지 말고 아래 3단계로 판단한다.

## 1. 즉시 수정 — 안 하면 현재 작업이 깨지는 것

- 내가 바꾼 코드가 의존하는 버그
- import 깨짐, 타입 에러, 테스트 실패
- 현재 커밋이 green이 되려면 반드시 필요한 수정

→ 같은 커밋 또는 직전 커밋에 포함.

## 2. 같이 수정 — 사소하고 안전한 것

- 내가 건드린 파일 안의 dead import, unused variable 제거
- 명백한 typo
- 기준: **3줄 이내, 테스트 변경 불필요, 사이드이펙트 없음**

→ 별도 커밋 (`chore: clean up ...`)으로 포함.

## 3. 기록 후 스킵 — 규모가 있거나 리스크가 있는 것

- 다른 모듈의 설계 문제, 리팩토링이 필요한 패턴
- 수정 시 다른 테스트가 깨질 수 있는 변경
- 기준: **3줄 초과, 또는 영향 범위를 확신할 수 없는 것**

→ issue 생성 (`gh issue create --title "Follow-up: ..." --label deferred`) 또는 PR 본문 `## Deferred` 섹션에 기록. 절대 무시하지 않는다.

## 원칙

- "범위 밖"은 안 하는 이유가 아니라, **어떻게 처리할지** 판단하는 입력이다.
- 발견한 문제를 기록 없이 넘기는 것은 금지. 깨진 유리창을 방치하지 않는다.
