# Plan Review Checklist

Plan 단계에서 구현 전에 아래를 검증할 것. 구현 후 발견하면 비용이 크다.

## 배치 (Placement)
- 새 함수/클래스를 어디에 놓는가? 이웃 코드와 응집도가 맞는가?
- 기존 모듈의 책임을 확장하는가, 아니면 이질적인 관심사를 끼워넣는가?
- "이 모듈이 하는 일을 한 문장으로 설명할 때 새 코드가 포함되는가?" — No면 다른 곳.

## SSOT (Single Source of Truth)
- 같은 지식(경로 패턴, 포맷, 상수, 변환 규칙)이 두 곳 이상에 표현되는가?
- 표현 형태가 달라도(Path 객체 vs 문자열) 근본 지식이 같으면 중복이다.
- 중복 발견 시: 상수/함수로 추출하고 한 곳에서만 정의.

## 데이터 흐름 (Data Flow)
- 같은 개념(예: 경로, ID)이 여러 레이어를 통과할 때 변환이 일관적인가?
- 한쪽에서는 resolve하고 다른 쪽에서는 안 하는 비대칭이 있는가?
- 비대칭이 의도적이면 주석으로 명시. 아니면 통일.
